架构 · Architecture

┌─────────────────────────────────────────────────────────────┐ │ Web UI (React + shadcn) │ │ ↕ REST │ │ master (Rust) │ │ ├─ axum (HTTP API) │ │ ├─ tonic (gRPC · mTLS 反向隧道) │ │ └─ PostgreSQL │ │ ↕ gRPC stream │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ │ │ 入口 │←→│ 中转 1 │←→│ 中转 N │←→│ 家宽出口 │ │ │ │ 商业 IP │ │ IPLC │ │ ... │ │ 固定 IP │ │ │ └──────────┘ └──────────┘ └──────────┘ └──────────┘ │ │ ↑ 任意 N 跳路径数组，统一 mTLS，对称节点 │ └─────────────────────────────────────────────────────────────┘ 数据模型：forward { path: [node_a, node_b, ..., node_n] } 每个节点同时是上一跳的出口 + 下一跳的入口，对称设计。

风险 · Risk Register

HIGH
Rust 入门 + 业余时间，tonic / sqlx / mTLS 学习曲线陡
缓解：P0 预热阶段先做最小 demo（master+node+gRPC ping），过关再进 P1。卡住超 1 周立即评估降级方案。
MID
入口节点带宽成本不可控
缓解：P5 计费上线前必须算清单客户成本，定价覆盖 3 倍带宽成本以应对突发。
MID
多级连跳 N 跳数据面调试复杂
缓解：P1 数据模型 day1 设计为 path 数组而非 in/out 二元；P2 强制 trace ID 贯穿全链路日志。
LOW
家宽节点 NAT 穿透 / 断线重连
已确认家宽 IP 固定，简化为标准反向隧道 + 心跳重连，无需 STUN/TURN。

关键决策 · Decision Log

2026-05-25
技术栈：Rust + tonic + axum + PostgreSQL
理由：性能 + 内存安全 + 单二进制部署，且参考 relay 已验证可行。
2026-05-25
转发内核：tokio copy_bidirectional（不写零拷贝）
理由：家宽带宽是瓶颈非 CPU，入门难度大，先够用，性能不足再换 splice(2)。
2026-05-25
协议层：L4 透传，不解析任何上层协议
理由：客户跑 SS/Trojan/VLESS 是黑盒，对平台等价于普通 TCP 流，工作量收敛。
2026-05-25
拓扑：路径数组 path[]，不区分入口/出口角色
理由：天然支持任意 N 跳级联，避免后期改数据模型。
2026-05-25
差异化：智能调度 + SLA + 拓扑可视化（非纯性能）
理由：卷不过 relay 的零拷贝，但 relay 没做"自有节点池 + 自动选优 + SLA 报告"。
