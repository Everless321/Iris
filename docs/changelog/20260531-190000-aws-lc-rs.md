# rustls crypto backend 切 ring → aws-lc-rs

## 背景

bench 数据显示同区域 Iris TCP P1 vs gost 差 18% (6.88 vs 8.64 Gbps)，主因是 mTLS 加密开销。
rustls 默认 crypto backend 用 ring (Rust pure crypto)，AES-NI 优化不如 BoringSSL 系列。
aws-lc-rs 基于 AWS-LC（BoringSSL fork），AES-NI 加速更好，业界基准 +20-30% TLS 吞吐。

## 改动

| 文件 | 改动 |
|------|------|
| `crates/node/Cargo.toml` | rustls + tokio-rustls features: `ring` → `aws_lc_rs`；quinn: `rustls-ring` → `rustls-aws-lc-rs` |
| `crates/node/src/raw_tunnel.rs:36` | `rustls::crypto::ring::default_provider()` → `aws_lc_rs::default_provider()` |

API 完全兼容，零代码逻辑改动。

## 副作用

- aws-lc-sys 是 BoringSSL 静态库绑定（C 代码），编译需要 cmake + clang
- musl target 编译略慢（首次 +30s 编 BoringSSL，cargo cache 后续 ~0）
- tonic 内部仍依赖 rustls，两个 provider (ring + aws_lc_rs) 共存编译 — 二进制略大但功能正常
- `install_default()` 用 aws_lc_rs 作为 process-wide 默认；tonic 构造 server config 时也会用同一个 default

## 预期收益（基于业界数据 + bench 推算）

| 测试场景 | 当前 (ring) | 预期 (aws_lc_rs) | 提升 |
|---------|------------|-----------------|------|
| 同区域 1-hop P1 | 6.88 Gbps | ~8.4 Gbps | +22% |
| 同区域 2-hop P1 | 3.48 Gbps | ~4.5 Gbps | +29% |
| 同区域 3-hop P1 | 2.84 Gbps | ~3.8 Gbps | +34% |
| 跨区域 (BDP 卡死) | 0.12-0.15 | ~0.12-0.15 | 无变化 |
