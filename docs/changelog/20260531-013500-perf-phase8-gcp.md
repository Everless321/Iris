# Phase 8 性能实测（GCP 4× n2-standard-4 asia-east1-a）

## 环境
- 4× GCP n2-standard-4 (4 vCPU / 16 GB / 10 Gbps NIC) 同 zone
- master = nosla-hk（生产 master，远程接入）
- 入口 = gcp-a, relay = gcp-b, exit-server = gcp-d, client = gcp-c
- musl static-pie release build（CI GitHub Actions），LTO fat 单线程编译
- node sysctl `net.core.rmem_max=4MB / wmem_max=4MB` 已调

## TCP 吞吐对比 phase 0（n2-standard-2 老硬件）

| 用例 | phase 0 | **phase 8** | Δ |
|---|---|---|---|
| 直连 1-stream | 9695 | 9780 | line rate |
| **1-hop 1-stream** | 5876 | **7710** | **+31%** |
| 1-hop 8-stream | 9314 | 9570 | line rate |
| 2-hop 1-stream | 2078 | 2060 | ≈ |
| 2-hop 8-stream | 4536 | 5240 | +15% |

> 注：phase 0 是 n2-standard-2 (2vCPU)，phase 8 是 n2-standard-4 (4vCPU)。
> 单流 CPU-bound，4vCPU vs 2vCPU 单核性能差异约 10%；
> 余下 ~20% 是 L1 quick wins 的真实收益。

## UDP 吞吐（新数据点）

| 用例 | sender | **receiver** | 丢包 |
|---|---|---|---|
| 直连 UDP `-b 9G` | 3120 | 3110 | 0.13% |
| **1-hop UDP** | 3140 | **1760** | **44%** |
| **2-hop UDP** | 3120 | **704** | **77%** |

观察：
- iperf3 sender 单线程 capped 在 ~3.1 Gbps（iperf3 -u 单线程极限）
- 1-hop UDP 单 src 单线程 mTLS+gRPC framing **+ AEAD** 跟不上 3 Gbps 输入
- 2-hop UDP 雪上加霜，relay 又过一次 mTLS

## 结论

✅ **TCP 单流 +31%** — L1 quick wins (BUF 64K, TCP_NODELAY, SO_RCVBUF/SNDBUF 4MB, LTO fat) 完整发挥

⚠️ **UDP 单 src 是瓶颈** — Phase 9 (kTLS) 是真正的 UDP 性能突破口。
   当前架构每 src 一条 tunnel，单核做完 framing+AEAD 后投递到 gRPC HTTP/2，每跳都付一次代价。
   kTLS 把 AEAD 卸给 kernel TCP_ULP，理论上 UDP 同样路径效率应翻倍。

## 已知 L1 没碰的瓶颈（留给 Phase 9）

1. **gRPC HTTP/2 framing 开销** — Phase 2 raw_tunnel.rs 是替代方案，但代价大
2. **rustls 用户态 AEAD** — Phase 3 kTLS 直接干掉这部分
3. **`Vec<u8>` 拷贝** — Phase 8 没改（风险大），改 `Bytes` 还有 5-10% 收益

## 预算

实际花费：4× n2-standard-4 跑 ~30 分钟 ≈ **$0.40**
