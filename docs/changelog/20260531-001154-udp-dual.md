# UDP 数据面 + TCP/UDP 双协议同端口

## 背景
当前 UDP 是伪功能：UI/DB/proto/master 都有 `protocol` 字段，但节点端 `forward.rs` / `dataplane.rs` 全部用 `TcpListener::bind` —— 用户选 UDP 保存后，节点根本收不到 UDP 包。

## 目标
1. 同一条 forward 可同时转发 TCP 和 UDP（DNS:53、游戏服、Minecraft 同端口同时）
2. 节点端补全 UDP 入口/出口/隧道路径
3. 不破现有 TCP 行为，可滚动升级

## 架构（C 方案：复用 gRPC Tunnel + Chunk header 标 session）
- 一条 forward 一条常驻 mTLS gRPC `Tunnel` stream（TCP/UDP 共用）
- TunnelHeader 加 `udp_src_addr` 字段：非空 → 这是一条 UDP 隧道
- 每个 `Chunk.data` 装一个完整 UDP packet（不分片，UDP 本身有 MTU 约束）
- 入口节点维护 `src_addr → tunnel_tx` map；出口节点维护 `(forward_id, src) → UdpSocket` 反向 map
- session idle 60s GC

## 已知边界
- **node 启动后不动态加载新 forward**：master 端新加 forward 后，node 必须重启才能 listen 新端口。改 SyncConfig 推送 diff 后续做。
- **UDP 出口不做 failover**：UDP 无连接，无法判断"连不通"，只取首选 target。
- **session 上限**：当前无硬上限，依赖 60s idle GC 控制 hashmap 大小。生产建议加 max_sessions 配置。

## 协议字段取值
| 输入（兼容） | 规范化存储 |
|---|---|
| `tcp` | `tcp` |
| `udp` | `udp` |
| `tcp+udp` / `both` / `tcp,udp` / `udp+tcp` | `tcp+udp` |
| 其它 | 400 拒绝 |

## 不做
- ❌ QUIC 内部封装
- ❌ ICMP 转发
- ❌ UDP 包分片（MTU 用户场景下用不上）
- ❌ migration 0008（schema 不变，应用层校验）
