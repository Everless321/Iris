# mTLS hardening: per-node SAN + SNI 身份绑定

## 背景

当前 mTLS 实现里所有 dial 端都用 SNI=`localhost`：
- master server cert SAN = `[localhost, 127.0.0.1]`
- node cert SAN = `[localhost, node_id]`（已含 node_id，但 client 端没启用）

后果：任何持有 valid CA 签发证书的节点都能冒充任意其他节点——攻击者拿到 nodeA 的 cert，可以伪装连 nodeB 的下游而通过 mTLS。

## 目标

让 client 端在 dial 时把 SNI 设为目标节点的稳定身份名（node_id 或 `zhuanfa-master`），rustls 会校验对端 cert SAN 必须匹配 SNI，从而绑定 cert 到具体身份。

## 改动清单

| 文件 | 变更 |
|------|------|
| `crates/common/src/lib.rs` | `ensure_dev_certs`: server.pem SAN 加 `zhuanfa-master`；启动时自动检测缺该 SAN → 重签 server pair |
| `crates/node/src/main.rs` | line 73 SNI `localhost` → `zhuanfa-master` |
| `crates/node/src/dataplane.rs` | `connect_dataplane(ctx, addr)` → 加 `peer_node_id` 参数；try_open 透传 |
| `crates/node/src/raw_tunnel.rs` | `open_next_hop` / `try_open` 加 `peer_node_id` 参数；ServerName 用 peer_node_id |
| `crates/node/src/quic_tunnel.rs` | `open_next_hop_inner` dial SNI 从 `localhost` 改对端 node_id |
| `crates/master/src/api.rs` | probe spawn 内 `tls.clone().domain_name(from_id)` 按 per-call 设置 SNI |

## 滚动升级安全性

- **Cert 无需重签**：现有 node cert 已含 `node_id` SAN（line 119 of common/lib.rs 早有此设）
- **保留 `localhost` SAN**：master server.pem + node cert 都保留 `localhost`，老 client 仍能用旧 SNI 连通
- **master server cert 自动迁移**：发现缺 `zhuanfa-master` SAN → 删 server.pem + server-key.pem 重签（不动 ca / node cert）
- **部署顺序**：master 先，node 后
