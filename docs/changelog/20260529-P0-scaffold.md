# P0 · Rust 预热 + 项目骨架

日期：2026-05-29

## 待办
- [x] 搭 Cargo workspace（proto / common / master / node 四 crate）
- [x] proto 定义最小 Control.Heartbeat service
- [x] common：rcgen 自动生成 CA + server/client 证书（mTLS）
- [x] master：tonic server，7443 监听，加载证书，记录心跳
- [x] node：tonic client，启动连 master，每 5s 发心跳
- [x] mTLS 跑通：master 验证 client 证书
- [x] `cargo build` + 本地端到端验证 master/node 互通

## 技术决策
- protoc 用 `protoc-bin-vendored`，免系统依赖
- 证书生成用 `rcgen 0.13`，master 首次启动自动生成到 `./certs`
- P0 同机验证，node 直接读本地 certs；自动 enrollment 留到 P2

## 执行结果
- `cargo build` 全绿（1m11s 首次编译）
- master 启动自动生成 mTLS 证书到 `./certs`，监听 0.0.0.0:7443
- node 用 client 证书完成 mTLS 握手，每 5s 发心跳，master 正常 ack
- 端到端验证日志：seq=1,2,3 心跳往返成功，证明 gRPC + mTLS 链路打通
- **P0 结论：技术栈可行，进入 P1**

## Docker 化验证（补充）
- master/node 地址、证书目录、node_id 全部 env 化（ZF_LISTEN / ZF_MASTER / ZF_CERT_DIR / ZF_NODE_ID）
- node 增加「等证书 + 连接重试」逻辑，适配容器启动顺序不确定
- Dockerfile 单阶段（编译运行同环境，规避 glibc 兼容；Docker Hub 当前不通，复用本地 rust:1.88-bookworm）
- docker-compose.yml：master + node 共享 certs volume，node 通过服务名 master:7443 互联
- **容器内验证通过**：node-docker-1 经 mTLS 与 master 完成 seq=1..4 心跳往返
- 注意：证书 SAN 含 localhost，node 用 domain_name("localhost") override SNI，故服务名连接 + 证书校验均成立
