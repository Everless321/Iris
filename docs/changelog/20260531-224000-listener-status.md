# listener 状态上报：node→master→UI 发现 OS 层端口冲突

## 背景
之前 master 只做 DB 层端口冲突 check，不知道 node 上 OS 层端口被其他进程
占用（如 sshd 占 22）。结果 UI 显示 forward 正常但实际 bind 失败，静默
失败。本次加上 node 上报 listener 实际 bind 状态 + UI 显示徽章。

## 改动文件 (7)
- `crates/proto/proto/control.proto` HeartbeatRequest 加 listener_states[] + 新 message ListenerState
- `crates/node/src/main.rs` spawn_forward 内 probe_bind() 预检 + ActiveForward.status + heartbeat 携带
- `crates/master/src/main.rs` ListenerStateView 共享内存 + heartbeat handler 写入
- `crates/master/src/api.rs` AppState 加视图引用 + list_forwards 注入 listener_status
- `crates/master/src/models.rs` Forward DTO 加 listener_status + ListenerNodeStatus
- `web/src/lib/api.ts` Forward type 加 listener_status?
- `web/src/pages/Forwards.tsx` 加 Listener 列 + ListenerBadge 组件（绿/黄/红/灰 + tooltip）

## prod 实测（commit f4d0c7f, deploy 后）
| 场景 | 结果 |
|---|---|
| 空闲端口 18901/tcp hawaii | `ok=true` ✅ |
| 占用 SSH 端口 22/tcp hawaii | `ok=false error="tcp bind 22: Address in use (os error 98)"` ✅ |
| 多入口 hawaii+att:18903/tcp 都空闲 | 两条都 `ok=true` ✅ |
| update 改端口到被占 22 | reconcile 重启 + probe → `ok=false EADDRINUSE` ✅ |

## 设计要点
- **probe 后 drop 再 spawn**：~1ms TOCTOU 窗口，SO_REUSEADDR 已开避免冲突
- **内存视图不持久化**：master 重启后 5s 心跳重建
- **heartbeat handler retain** 清掉 node 不再上报的旧条目（forward 删除/不再入口）
- **向后兼容**：旧节点上报空 listener_states，master retain 保留旧状态；UI 显示「等待心跳」
- **list_forwards 只看 hops[0]** 入口节点：中转/出口节点不显示徽章
- **UI 徽章**：≥1 入口节点失败 → 黄/红；hover tooltip 显示每节点详细错误
