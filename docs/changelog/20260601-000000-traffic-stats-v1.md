# 流量统计 V1: per-forward bytes_in/out

## 改动 (commit bb7b400, 13 文件 +276/-36)

### 数据采集 (node)
- **dataplane.rs** 新增 `TrafficCounter { bytes_in/out: AtomicU64 }` (Relaxed fetch_add ~5ns，9Gbps 无感知)
- **forward.rs** `run_single_hop` 改 `copy_bidirectional` → split + 手动 loop 累加 (单跳 TCP 入口)
- **dataplane.rs** `run_multi_hop_entry / handle_entry_conn / bridge_tcp` 透传 traffic 参数 (多跳 TCP 入口)
- **raw_tunnel.rs** `handle_entry_tcp` 加 traffic 参数（多跳 raw 路径）
- **udp_forward.rs** `run_udp_{single,multi}_hop` recv→add_in, send_to→add_out
- **quic_tunnel.rs** `udp_recv_loop` send_to(src) 成功后 add_out

字节定义：
- `bytes_in`  = 入口节点 accept 后从客户端 read 的字节数（用户上行）
- `bytes_out` = 入口节点 write 给客户端的字节数（用户下行）
- 仅入口节点统计，中转/出口不计避免重复

### 协议 (proto)
- `HeartbeatRequest.traffic_stats: repeated TrafficStat`
- `TrafficStat { forward_id, bytes_in: u64, bytes_out: u64 }` 累计语义

### Master
- `ControlSvc.traffic_last: Arc<RwLock<HashMap<(node_id, forward_id), (u64, u64)>>>`
- heartbeat handler 算 delta（current < last → node 重启，delta = current）
- migration **0008_forward_traffic.sql** 加 INTEGER NOT NULL DEFAULT 0 列
- `Forward` DTO + `ForwardRow` 加字段
- `/metrics` 加 `iris_forward_bytes_{in,out}_total{id,name,port}` counter

### UI
- `Forwards` 表加「流量」列，`formatBytes` 自适应 KB/MB/GB
- 上下行分两行显示 + Tooltip 显示原始字节数 + 合计

## prod 实测 (commit bb7b400, deploy 后)

5 次 `curl www.google.com:80` 通过 hawaii:18810 → 经 Iris 转发：
- **bytes_in = 390** (5 × ~78B HTTP request headers)
- **bytes_out = 407950** (5 × ~80KB HTTP response)
- /metrics counter 同步 `iris_forward_bytes_{in,out}_total`
- listener_status 兼容不变

## 性能影响
- AtomicU64 Relaxed fetch_add 每包 ~5ns
- heartbeat payload 每 forward 增加 ~30 bytes (TrafficStat protobuf)
- 5s 心跳 × 100 forwards 仅 3KB 网络开销
- 业务数据面无感知 (Phase 8 实测 9.5Gbps 单流 P1 不变)

## 设计取舍
- **累计语义而非 delta 语义**：node 重启不会让 DB 倒退（master 检测 current<last 时把 delta=current）
- **不持久化 last_reported**：master 重启第一轮少计一轮（≤5s），可接受
- **仅入口统计**：避免多入口节点 LB 时重复计数（按 (node_id, forward_id) 维度天然不冲突，但中转节点不应再算）
