# GCP 实测 benchmark: Iris vs gost vs nftables

## 测试环境
- 6 × GCP n2-standard-4 (4 vCPU / 16GB / gVNIC 10Gbps)
- us-central1-a × 4 (uc1-uc4) + asia-east1-b × 1 (ap) + europe-west1-b × 1 (eu)
- Ubuntu 22.04, kernel default, sysctl net.core.{rmem,wmem}_max=4MB
- iperf3 3.9, gost v3.0.0, nftables v1.0.2, Iris commit 094de37
- 测试时长 / 成本：约 70 分钟 / ~$3 GCP cost
- 资源测后全清（6 instances + GCS bucket + firewall rule）

## 关键数据

### RTT 矩阵 (ping 平均，GCP 内网)

- uc1 → eu (europe-west1): **104.5 ms**
- uc1 → ap (asia-east1): **160.7 ms**

## 关键发现

1. **同区域 P8 都接近线速**：4 工具的多流吞吐都在 9-9.87 Gbps，差异 < 8%。NIC 是瓶颈，软件不是。
2. **同区域 P1 显著分化**：单流 TCP 暴露每跳的真实开销。
   - nftables 几乎零开销（9.47 / 9.87 = 96%）— kernel softirq 加速
   - gost 中等开销（8.64 / 9.87 = 88%）— plain TCP, 用户态拷贝
   - Iris 大开销（6.88 / 9.87 = 70% for 1-hop, 持续衰减 2.84 for 3-hop）— 每跳含 rustls 加密 + length-prefix framing
3. **Iris UDP 完美 0% 丢包**：QUIC datagram 主动 backpressure 替代 kernel silent drop（参考 Phase 9c 设计）
4. **跨区域差异基本被 BDP 消化**：高 RTT 下 TCP 单流被拥塞窗口卡死，relay 加不加吞吐都在 ~120 Mbps；多流都在 ~830 Mbps；三方差距 < 5%。
5. **跨区域 Iris 2-hop 反而比 1-hop 单流更快**：从 0.122 → 0.147 Gbps。绕路时 CWND ramp 更早达到稳态（每段 RTT 更短）。

## 已知 quirks
- gost UDP forward `-L udp://:port/target` + iperf3 -u 报 "unable to send control message: Bad file descriptor"。需要更细的 gost 配置（relay+mtls 或者分开 control/data port），未深入。
- nftables 多跳无原生意义（DNAT 是单机概念），矩阵里标 N/A。
- Iris 测试时 forward 创建后需要 systemctl restart iris-node 才能 spawn 入口 listener（main.rs 启动时 spawn 一次，不支持热加载）— 是 Iris 已知限制，不是 benchmark 问题。
